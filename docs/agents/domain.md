# Domain docs

## Read before exploring

This is a single-context project. Read the root `GLOSSARY.md` when it exists, then relevant decisions under `docs/adr/` before exploring the affected feature.

If a root `GLOSSARY-MAP.md` is introduced later, follow its links to the relevant context glossaries and context-scoped ADRs.

If these documents do not exist, proceed silently. Create domain documents through domain-modeling when terminology or decisions actually need recording.

## Vocabulary

Use glossary terms consistently in specifications, tickets, tests, and proposals. When an undefined term is necessary, check the codebase vocabulary before proposing a glossary addition.

## Decision conflicts

When a proposal conflicts with an existing ADR, name that ADR and explain the conflict before proposing a replacement.

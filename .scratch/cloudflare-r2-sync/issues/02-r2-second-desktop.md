# 02: Support R2 onboarding on a second desktop

**What to build:** 第一台电脑使用私有 R2 桶同步后，第二台新电脑通过配置导入及仓库密钥恢复下载数据，并把后续编辑同步回第一台。

**Blocked by:** 01 — Support manual S3 synchronization without an official account.

**Status:** resolved

**Started:** 2026-10-28，工作分支 `v2`；自动化验证先使用独立工作空间和私有 S3 协议测试服务，真实 R2 与第二台电脑另行验收

- [x] R2 参数配置、导入、重启后持久化及双向手动同步完成协议层闭环；真实 R2 按下述限制待验收。
- [x] 既有配置导出/导入通过真实往返验证；若不对称，在保持旧格式可读的前提下修复。
- [x] 仓库密钥恢复步骤明确，导入配置不擅自替换既有仓库密钥。
- [x] 私有 S3 测试服务限定单桶凭证可工作且拒绝账户级列桶；真实 R2 的受限凭证仍待验收。公开访问、自定义域名及 Workers 均非前置条件。
- [x] 测试记录区分模拟 S3 验证与实际 R2 双工作空间验证；未取得云端访问时明确标记后者待验收。
- [x] 已有数据的工作空间加入流程保留其未上传变更，配置错误或切换失败保留来源。

## Answer

复用现有 JSON / ZIP 配置导入导出格式，通过真实 HTTP 导出和导入验证连接字段、配置持久化及重新加载后的状态。导入不替换已有数据仓库密钥、不自动开启同步、不删除本地文件。发现空包或截断密文会触发解密 panic，因此在共享解码边界把损坏包转换为配置错误，S3 和 WebDAV 均保留旧格式可读。

相关验证位于 `kernel/api/sync_s3_onboarding_test.go`，结合任务 01 的真实同步入口与私有 S3 协议服务双工作空间测试验证传输与错误恢复。配置往返和数据传输由不同测试覆盖，没有把未执行的实际 R2 联调算作自动化通过。

操作及验收说明见 [desktop-acceptance.md](../desktop-acceptance.md)。没有真实 R2 凭证，尚未创建云端资源，也没有构建或发布客户端。真实 R2 的双向传输、受限凭证操作以及两台实体电脑仍需按该清单验收；任务 03 的冲突缺陷未解决前，不确认正式笔记使用安全。

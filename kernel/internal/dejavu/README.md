# 思源自用同步引擎补丁

本包包含 `github.com/siyuan-note/dejavu` 固定版本 `v0.0.0-20261011111741-4465ef631977` 的 20 个根包生产文件，保留原版权和 [AGPL-3.0 许可证](LICENSE)。原始文件的 SHA-256 记录在 [UPSTREAM.json](UPSTREAM.json)。`cloud`、`entity`、`util`、`lansync` 仍使用 `kernel/go.mod` 固定的上游版本，没有修改模块缓存，也没有本地路径 `replace`。

应用的根包引用统一指向本包，避免新旧 `Repo` 类型混用。应用其余依赖继续通过现有 Go 模块管理。这份源码用于使本仓库在普通 Go 构建和 CI 中得到相同的修复结果，不要求开发者额外安装源码补丁。

## 补丁范围

- `options.go`、`repo.go`：新增默认关闭的 `ContentFileIDs` 选项。应用仅在 S3 提供商启用；原有其他提供商保留原对象标识和比较方式
- `index_file.go`：新 S3 文件对象的 ID 使用版本域 `siyuan-content-file-v2`、路径、大小、毫秒时间与有序分块 ID 生成 40 位哈希。不同内容即使路径、大小和修改时间相同，也不会因时间粒度而复用同一对象。已有不同内容占用同一新 ID 时返回错误，保留原对象
- `diff.go`、`repo.go`：S3 比较已索引版本的内容，扫描磁盘时比较精确毫秒时间和大小；未变化的条目继续引用原对象，不改写旧快照。与原有扫描策略一致，外部程序若同时复用完全相同的大小与毫秒修改时间，磁盘扫描不能保证发现该编辑；应用正常保存会更新文件时间
- `store.go`：缓存按仓库路径、密钥摘要与对象 ID 隔离，避免不同工作空间或错误密钥取得另一上下文已解密的元数据
- `sync.go`：同伴来源在认证解密后重验受支持的 v1 或 v2 文件标识，保留已有来源路径，未知标识仍拒绝

其他根包生产代码保持原样。独立双进程测试覆盖同一秒、同一时间戳且等长的离线编辑，进入实际应用同步入口后检查两个版本均保留。

## 兼容规则

该补丁改变新 S3 文件对象的标识生成方法，不改变对象 JSON 结构、加密、压缩、分块、多项式、索引格式、密钥或恢复材料。对象 ID 仍为 40 位十六进制值。读取路径继续按索引中已有 ID 查找并认证解密，因此旧快照不会被改名或迁移；未经修改的上游引擎也能读取新对象。两个客户端都应升级至本分支版本，旧引擎自身的同秒冲突缺陷并未因此被修复。

`testdata/legacy-v1` 为固定上游写入的旧仓库夹具，密钥和内容均为公开测试数据。生成器直接导入固定上游包，与修复后的实现相互独立。需要重新生成时，从 `kernel/` 执行 `go run ./internal/dejavu/testdata/generate <新的输出目录>`，核对来源后再替换夹具；生成器拒绝覆盖已有目录。

兼容测试覆盖固定旧夹具恢复、错误密钥、损坏密文保留、新旧读者分别恢复旧快照和新快照，以及旧/新对象经云存储备份后在空仓库下载恢复；另在云端对象不可读时验证两种标识均可由同伴来源提供。云端测试使用本地协议适配器，不代表实际 R2 已验收。笔记本层的加密格式由应用既有回归测试继续覆盖，本包只处理不透明文件字节。

## 验证与升级

从 `kernel/` 运行 `go test ./internal/dejavu`，以及 `go test -tags "fts5 sqlcipher" ./model ./api -run 'TestS3Desktop|TestS3Onboarding|TestManualS3' -count=1`。Windows 应提供仓库要求的 C 工具链。常规内核全套测试自动包含本包与同秒冲突回归，不依赖环境变量，也不跳过该冲突用例。

升级上游时先按原始哈希识别上述六个文件的补丁，再同步根包和所引用子包的版本；复验兼容与完整应用测试。不要只替换 `entity.NewFile`，因为磁盘索引、版本比较、旧对象引用、同伴来源和缓存边界必须共同保持一致。
